# 11 · 技术栈与架构定版

Type: grilling
Status: resolved
Claimed: 2026-08-27
Resolved: 2026-08-27
Blocked by: 01, 07

## Question

依据「技术栈与架构调研」的推荐 + 「用户角色与端形态」的结论，定版技术栈与部署架构：

- 最终选型（前端/后端/数据库/部署），含「自研 vs 开源二次开发」的最终决断
- 部署拓扑：服务器、网络访问方式、备份基线
- 此决策难逆转、有真实取舍——建议落一条 ADR（docs/adr/0001）

## Answer

### 第一轮（2026-08-27）

- **自研 vs 二开**：从零自研——TS 全栈是代理生产效率最高的形态；排期域是核心差异点而开源 ERP 最弱；账目口径非标准两头不贴；许可证无尾巴 ✅
- **技术栈**：待确认——用户要求先看四层对比（已出对比图，见第二轮）
- **服务器**：现有电脑复用 + 需要一键安装版本——厂内闲置电脑跑系统，交付物需含一键安装脚本 ✅
- **备份基线**：本地+移动硬盘双备份——每日 pg_dump 到服务器本地 + 每周拷移动硬盘 ✅

### 第二轮（2026-08-27）

- **技术栈定版**：四层全收——React19+AntD6 / NestJS11 / PG18 / Drizzle，TS 全栈单语言、类型贯通、AI 代理友好度最优 ✅
- **一键安装**：纳入交付物——一键脚本（Windows 开发机 + 厂内服务器各一套），作为「实施顺序」票的交付验收项 ✅
- **开发/生产环境**：都是 Windows——开发机 Windows 本机跑同一套 compose；生产机 Windows 跑 Docker Desktop（免费档）；有必要时用云服务搭环境 ✅

### 第三轮（2026-08-27）

- **生产机跑法**：Windows 装 Docker Desktop（免费档）直接跑同一套 compose（nginx+app+postgres）——开发/生产同构 ✅
- **云服务用途**：条件翻案——若厂内现有电脑配置吃不消（低于 2C8G 起），生产部署到云服务器（阿里云/腾讯云轻量）；默认仍在厂内 Windows 机 ✅
- **AI 出站**：厂内网络能出公网——服务器出站访问 LLM API（DeepSeek/qwen）无问题，票10 云端 API 方案直接可行 ✅
- **ADR**：落 ADR-0001——记录技术栈定版（docs/adr/0001）✅

### 第四轮（2026-08-27）

- **部署拓扑定版**：厂内 Windows 主 + 云翻案——默认厂内 Windows 机 Docker Desktop（免费档）跑同一套 compose，厂内浏览器 IP 直连；翻案条件：厂内机配置吃不消（<2C8G）→ 云服务器轻量 2C8G；备份每日 pg_dump 本地 + 每周移动硬盘 ✅
- **厂内访问方式**：IP 直连——浏览器直接输 http://192.168.x.x，零配置，免登录模式下最简单，2-3 台 PC 连同一 IP ✅
- **一键脚本形态**：安装+升级双脚本——①安装脚本（首次：装 Docker Desktop + 拉镜像 + 起服务）②升级脚本（以后：拉新镜像 + 重启），Windows 下 .bat 双击即用，厂里不需要命令行知识 ✅

### 已知代价/风险（选择而非隐患）

1. 厂内闲置电脑硬件寿命不确定——硬盘坏 = 数据风险，靠双备份兑底
2. 免登录 + 厂内 IP 直连 + 无 HTTPS——数据在局域网明文传输，厂内环境可接受，云翻案时必须补 HTTPS/访问控制
3. 排期域甘特/拖排组件是唯一前端风险点（AntD 无原生甘特），留票 05 技术验证
