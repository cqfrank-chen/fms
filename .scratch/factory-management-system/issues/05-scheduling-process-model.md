# 05 · 排期与工序域模型

Type: grilling
Status: resolved
Claimed: 2026-08-27
Resolved: 2026-08-27
Blocked by: 04✅

## Question

按等级二（APS 建模先行）敲定排期域模型：

- 产线/机台/工作中心、工序、工艺路线、标准耗时、产能（班次/日产能）的实体与关系
- 排程看板的交互形态：日/周视图、拖拽粒度（计划单级还是工序级）
- 工序报工（进度回填）的最小形态——为将来 IPQC 挂点留缝
- 与「工序耗时数据整理」票的结构化产出对齐

## Answer

### 第一轮（2026-08-27）

- **排期单元**：计划单级——整张计划单作为一个可拖拽任务块（票03挂起假设成立），排期表上一行一个计划单；不展开工序细节 ✅
- **产能模型**：工序产能池——每道工序一个产能池（设备数=可并行台数），排期只算工序负载，不管具体哪台机器；对应票04参数模型 ✅
- **排期约束**：交期硬约束+产能软约束——交期冲突（排完超期）标红提示（票10预警），允许硬排（客户已同意延期）；产能不阻塞 ✅
- **排期池范围**：已确认全进池——所有「已确认」计划单自动进入排期池（可筛客户/交期/产品），已排可拖拽改期，未排显示待排区 ✅

### 第二轮（2026-08-27）

- **看板视图**：甘特图——横轴时间（可切周/月）、纵轴工序产能池，计划单任务块按时间段排列可拖拽；AntD 无原生甘特需引第三方库（票11技术验证点）✅
- **拖拽粒度**：拖计划单——只拖整张单（改开工/完工日），工序时间由产能池自动推算（数量×单件耗时÷设备数），系统提示经过哪些工序占多少产能 ✅
- **报工形态**：行级报工——计划单行录完成数量，整单进度=行进度聚合（票03状态机）；工序耗时只在排期推算用，不单独录；IPQC 挂点预留到行级报工 ✅
- **交期冲突展示**：看板标红——排完超期的任务块红色边框+「超期X天」提示，待排区正常显示 ✅

### 第三轮（2026-08-27）

- **甘特库选型**：验证后定——frappe-gantt（开源MIT）/ dhtmlx-gantt（商业）候选，开工时技术验证票决定；核心要求：拖拽改时间、自定义列、事件回调 ✅
- **产能推算**：推算+可覆盖——拖排自动推算（数量×单件耗时÷设备数）显示在任务块；计划员可覆盖单个任务工期，「覆盖值」与「推算值」区分标识；票04数值未填时占位提示待补参数 ✅
- **排期状态**：独立排期状态字段——未排期/已排期，拖进时间槽自动变已排期；独立于票03五态状态机，由排期表驱动，避免双写 ✅
- **排期×报工联动**：报工驱动看板——行报工达标→任务块变绿/打勾；首行报工>0→进行中色；完工→已完成；看板状态从报工事件驱动不手动改 ✅

### 第四轮（2026-08-27）

- **覆盖值标识**：色标+可恢复——推算值灰色普通数字、覆盖值橙色加粗+铅笔标记，一眼区分人工改动；恢复按钮一键回到推算值 ✅
- **实体关系**：三层标准结构——工作中心（工序产能池，如「钻孔组」）→ 工序（字典13道，挂设备数/耗时）→ 计划单排期任务（引用工序序列）；工序字典全局共享，产品类型挂默认工序序列（票04），计划单排期按序列算总耗时 ✅
- **时间粒度**：天级——拖拽粒度整天（任务块占X天），时间轴刻度=天；换型时间（分钟级）折入天粒度，不影响交期判断 ✅

### 设计闭环（跨票对齐确认）

- 票04 工序字典/参数模型 → 三层实体（工作中心/工序/任务）→ 排期推算 → 报工回填 → 看板状态：03/04/05/10 四张票在这张票上全部对齐
- 票03 挂起假设「整张计划单作为一个排期任务」正式成立（第一轮 Q1 确认）

### 已知代价（选择而非隐患）

1. 工序耗时数值未填前，看板推算工期为占位提示「待补参数」——排期精度依赖票04运行期前端配置
2. 天级粒度下换型时间（分钟级）折入天，多型号同日换型频繁时排期偏粗
3. 工序产能池不区分具体设备台——设备故障/保养无法在排期里体现（等级二可接受，二期设备级再说）

### 决策修订（2026-08-28，用户原型反馈触发）

- **排期单元修订**：从「计划单级」改为「计划单行级」——每个产品行一个可拖拽任务块，分别拖排/分别报工；计划单状态仍由行进度聚合（票03状态机不变）；甘特图按行显示任务块。触发点：票09原型用户反馈「一个计划单有多个产品行，应该有同一计划的不同行的排程和报工」
- 修订影响：第一轮 Q1「排期单元=计划单级」作废，以本条为准；甘特图/拖排/核验面板均按行级实现
