# 12 · 数据迁移与切换

Type: grilling
Status: resolved
Claimed: 2026-08-27
Resolved: 2026-08-27
Blocked by: 03, 06

## Question

敲定从 Excel/纸单到新系统的迁移与切换方案：

- 迁移范围：历史订单、库存快照、往来余额各迁多少（全量 vs 近期）
- 迁移工具与校验：Excel 模板导入？
- 并行切换策略：新旧并行多久、以谁为准、何时切

## Answer

### 第一轮（2026-08-27）

- **历史订单范围**：主数据全量 + 在途必迁——产品目录/客户档案/供应商档案全量迁；在途未完成的订单/计划单必迁；已完成的旧订单不迁（留 Excel 备查）✅
- **库存期初**：成品期初快照——切换日按 SKU 记一个数量作新系统库存起点；原料侧不入库存账（票06）无需迁移 ✅
- **往来余额**：余额不迁 + 旧账留 Excel——切换日若有未结清旧账，留在 Excel 线下催收/还款，新系统从零记新账；对账单/账龄只覆盖新账（用户明确选择，非误解）✅
- **切换策略**：定点切换——选一个切换日（建议月初），切换日前旧 Excel 继续用、切换日起新订单全进新系统、旧表只留备查不再更新；不做并行双记 ✅

### 第二轮（2026-08-27）

- **迁移工具**：系统内 Excel 导入——内建数据导入功能（Excel 模板 + 上传导入 + 错误报告），随系统一起开发，文员自己就能导 ✅
- **主数据录入**：两者结合——模板批量导入 + 系统内手录结合（具体方式第三轮确认）✅
- **在途单录入**：模板导入——在途订单/计划单按 Excel 模板逐单导入（含客户/产品/数量/交期/包装），导入后确认状态 ✅
- **切换日选点**：备齐即切——数据备齐那天就切，不设固定切换日（与推荐「月初切换」不同，代价第三轮确认）✅

### 第三轮（2026-08-27）

- **主数据录入方式**：首次导入+日常手录——首次一次性用 Excel 模板批量导入（产品目录/客户档案/供应商档案），后续新增在系统内手录 ✅
- **备齐即切确认**：接受月中切换——切换日可能落在月中，切换当月月度统计横跨新旧两套，对账时人工区分（票08月度口径）✅
- **切换准备清单**：边用边补——切换后第一周系统数据不完整，按「主数据→期初库存→在途单」优先级边用边补，业务量小硬扛（用户明确选择，非推荐项）✅

### 第四轮（2026-08-27）

- **边用边补确认**：确认——切换后按优先级边用边补，对账注意区分新旧 ✅
- **旧表归档**：归档保留——切换后旧 Excel/纸单归档不再更新但保留查询（历史订单/旧账还要用，票08旧账留 Excel）✅
- **导入校验**：自动校验+人工抽检——导入时系统自动校验（必填缺失/产品不在目录/客户不存在/数量为负/交期早于今天），错误行标红拒导出错误报告，改完重导；导入后人工抽检对照 ✅

### 已知代价（选择而非隐患）

1. 旧账留 Excel——新系统对账单/账龄只覆盖切换日后的新账，旧欠款系统里看不到，对账要两处看
2. 月中切换——切换当月月度统计横跨新旧两套，对账时人工区分
3. 边用边补——切换后第一周系统数据不完整，业务靠人脑补位
