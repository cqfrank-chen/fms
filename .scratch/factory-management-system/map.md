# 工厂管理系统 · 决策地图

## Destination

一份覆盖生产四域（订单→计划单、排期、仓储、账目统计）的一体化工厂管理系统可建规格：技术栈定版、系统架构、各域数据模型与边界、AI 接入方案与分期、数据迁移与实施顺序。按代理可直接消费的写法组织，产出后交给 /to-spec 拆 tracer-bullet 票据开建。

## Notes

- 部署：单厂自有工厂自用，单租户；数据模型预留多厂/多组织字段
- 排期能力：等级二（APS 建模先行）——工序/耗时/产能按 APS 标准建模，界面人工拖排，自动排产算法待数据积累后二期补上
- 账目口径：经营统计（订单营收、物料/生产成本、利润视图）+ 往来账款（应收/应付/对账单）；标准财务做账出界
- AI：全面接入——订单解析、自然语言查数、排产建议、异常预警、报表生成全集入图，分期由「AI 能力分期」票排定
- 现状：流程主要跑在 Excel/纸单上，需要数据迁移与切换设计
- 实施主体：代理自建；规格 agent-ready
- 会话语言中文；术语以根目录 CONTEXT.md 词汇表为准
- 每个会话开工前先读 AGENTS.md 与 docs/agents/issue-tracker.md、docs/agents/domain.md；grilling 票同时加载 domain-modeling 技能

- [技术栈与架构调研](issues/01-tech-stack-research.md): 从零自研——React 19 + TypeScript + Ant Design 6 / NestJS 11 / PostgreSQL 18 + Drizzle ORM；Docker Compose 单机厂内部署 + frp/WireGuard 远程穿透；ERPNext 二开仅在需要完整财务/成熟 MRP 时翻案。详见 research/01-tech-stack.md
- [AI 接入方案调研](issues/02-ai-integration-research.md): 五项能力统一「确定性为骨、LLM 解释」——订单解析走多模态直出、查数先工具调用后受控 Text-to-SQL、排产预警走规则引擎、报表走模板+摘要；国内 API 月费约 30-300 元，不私有化。详见 research/02-ai-integration.md
- [订单与计划单域模型](issues/03-order-plan-domain-model.md): 产品目录+客户档案做主数据；订单一单多产品（行含单价+币种+行级包装要求）、单头交期+客户PO号；一单一计划单、订单确认自动生成草稿+人工审核；双五态状态机、进度自动推导；变更联动草稿重生成/确认后人工。详见票据 Answer
- [仓储域模型与质检接缝](issues/06-warehouse-model-qc-seam.md): 只管成品（原料由来料登记单轻登记+批次追溯）；成品批次=一计划单一批次；报工即触发入库草稿+仓管确认；出库挂订单可分批+OQC先检后出；盘点单+冲销纠错；安全库存标红预警；允许负库存。详见票据 Answer
- [账目口径建模](issues/08-accounting-scope-model.md): 现金收付制营收（收款=营收）+期间制成本（材料按采购月汇总+六类月填）；应收挂出库、应付挂来料登记单；收付款单核销双模式（核销+预收/预付）；四表导出给外部做账；一期单币种RMB。详见票据 Answer

## Not yet specified

- 各域字段级细化与校验规则——等域模型票落地后看是否需要单独票
- 自动排产算法选型与调参——等级二数据积累后的二期事
- AI 排产建议的具体模型路径——等 AI 调研结论 + 排期数据规范化
- 单据打印模板（计划单/出库单格式）——落地时可能冒出
- 质检系统对接协议细节——接缝字段定后
- 备份、容灾、数据安全策略
- 多厂扩展的启用路径（何时真正需要多租户）

## Out of scope

- 质检系统本体（IQC/IPQC/OQC 全流程建设）——只留集成接缝，另行立项
- 分拣系统、零售/视频流量运营——独立项目
- 标准财务做账（凭证、标准报表）——已有独立的做账系统调研
- 多工厂多租户的完整实现——本期仅数据模型预留
