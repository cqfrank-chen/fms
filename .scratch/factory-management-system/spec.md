## 1. 项目概述

单厂自有工厂自用的生产管理系统，覆盖生产四域一体化：

- **订单→计划单**：客户订单录入 → 自动生成计划单草稿 → 人工审核 → 状态机驱动
- **排期**：APS 等级二（建模先行）——工序产能池 + 甘特图人工拖排
- **仓储**：只管成品库存，原料轻登记；报工驱动入库、出库挂订单、OQC 先检后出
- **账目统计**：经营统计（现金收付制营收 + 期间制成本）+ 往来账款（应收/应付/对账单）

约束：单厂单租户（数据模型预留多厂字段）；质检只留集成接缝（IQC/IPQC/OQC 挂点），本体另行立项；现状 Excel/纸单需迁移；实施主体为 AI 代理。

| 层 | 选型 | 要点 |
|---|---|---|
| 前端 | React 19 + TS + AntD 6 | Ant Design Pro V6 脚手架；排期甘特图需引第三方库（frappe-gantt/dhtmlx 待验证） |
| 后端 | NestJS 11（TS） | module/controller/service 强约定；REST + 调度内置 |

| 部署 | 单机 Docker Compose | nginx + app + postgres（postgres 不暴露端口） |
| 生产机 | 厂内 Windows + Docker Desktop（免费档） | 配置吃不消（<2C8G）→ 云服务器翻案 |

## 4. 订单域（票 03 + 票 09 原型）

### 4.1 实体

**订单（Order）**：客户下达的生产需求单据
- 单头：客户档案引用、客户 PO 号、交期、备注
- 订单行（一单多产品）：产品目录引用 × 数量 × 单价（含币种） × 刻字需求 × 包装要求（复合）
- 包装要求：**复合选项**——包装盒/套袋/纸箱/不干胶 可多选，每项填规格；支持模板库保存复用 + 上传样式图

**计划单（Plan Sheet）**：一单一计划单，从订单整单生成
- 计划单行：产品 / 计划数量 / 包装要求 / 刻字 / 完成数量
- 行进度聚合出整单状态

### 4.2 状态机

订单五态：草稿 → 已确认 → 生产中 → 已完成 / 已取消
计划单五态：草稿 → 已确认 → 生产中 → 已完成 / 已作废

进度自动推导：计划单状态由行报工聚合；订单状态由计划单聚合联动。

### 4.3 事件链

```
订单确认 → 自动生成计划单草稿（预填目录默认值）→ 计划员审核 → 已确认
    ↓ 行报工（录完成数量）
    行进度聚合 → 计划单生产中 → 全部完成 → 计划单已完成 → 订单已完成 → 进归档
```

### 4.4 变更联动

- 草稿态变更：自动重生成
- 确认后变更：人工处置（编辑/作废重开）——**订单不走冲销**（冲销仅用于单据纠错）

### 4.5 界面决策（票 09 原型验证）

- 订单列表：状态/客户/单号筛选；已完成自动进归档区可反查
- AI 图片识别导入（票 10 一期）：上传客户邮件/微信传单/拍照 → 自动填客户/产品行/刻字/包装，低置信度标红待人工确认
- 订单详情/计划单反查：弹窗展示

## 5. 排期域（票 04 + 票 05，含票 09 修订）

### 5.1 实体关系（三层）

```
工作中心（工序产能池，设备数=可并行台数）
  └─ 工序（全局字典 13 道种子：下料/车削/钻中心孔/钻预热孔/螺纹/铣削可选/钎焊可选/铰孔/抛光/清洗/测试/包装）
      └─ 排期任务（= 计划单行，行级排期单元 ★票09修订）
```

### 5.2 关键决策

- **排期单元 = 计划单行级**（票 09 修订：每个产品行一个任务块，分别拖排/分别报工；计划单状态仍由行聚合）
- **报工按工序推进（I06 修订，整批逐道）**：配了工序路由的产品，报工 = 完成「当前工序」（行 route_seq 指针）；中间工序一次报满整批 → 自动推进路由下一道（换泳道/已排期顺延），末道报满才累计成品 → 计划单/订单完成 + 入库草稿。无路由产品成品直报（可分批）。排期池 = 已确认 + 生产中（逐道推进可见）
- 工序序列/耗时/设备/拓扑 = 可配置主数据（票 04，前端交互逐项填写；丙烷钻孔明显更慢需分列；单班 8 小时）
- 排期约束：交期硬约束 + 产能软约束（超期看板标红可硬排）
- 排期池：已确认计划单全进池（可筛客户/交期/产品）
- 排期状态：独立字段（未排期/已排期），不进五态状态机
- 报工驱动看板：行任务随工序推进换泳道（块标 [当前工序 x/y]，黄=已推进）；末道报满→成品完成→绿/打勾→完工

### 5.3 甘特图交互（票 09 原型验证）

- 时间粒度：天级；工序耗时自动推算（数量×单件耗时÷设备数）可覆盖（覆盖值色标区分+可恢复）
- 点击任务块 → 排期面板（选工序 + 开始日期 + 核验：工序负载/工期/交期判断）→ 确认排期
- 同工序重叠任务：贪心分层垂直错开
- 任务块点击弹订单行简介（客户/产品/数量/交期/刻字/包装/工序/报工进度/来源订单）
- 技术验证：frappe-gantt（MIT）vs dhtmlx-gantt（商业）——拖拽改时间/自定义列/事件回调

## 6. 仓储域（票 06）

| 实体 | 关键点 |
|---|---|
| 来料登记单 | 超轻量：日期/供应商/物料名/数量/批次号/检验状态（IQC 预留线下）；不维护库存；带金额生成应付 |
| 成品批次 | 一计划单一批次（FG-YYYYMMDD-NN）；入库/出库/追溯挂批次 |
| 入库单 | 报工事件自动触发草稿（预填产品/数量/批次）→ 仓管确认入账；草稿→已确认两态 |
| 出库单 | 挂订单、行引用订单行、可分批；带 OQC 状态（待检/合格放行/免检），待检不可确认；带包装要求快照 |
| 盘点单 | 实盘数 → 差异 → 盘盈/盘亏调整单 → 确认校准，全程留痕 |
| 冲销 | 已确认单据纠错：开等额反向单抵销再开正确单，流水完整可审计 |

决策：只管成品；允许负库存；安全库存标红预警；退货补发一期不做。

### 事件链

```
报工 → 入库单草稿 → 仓管确认 → 库存+
出库确认（OQC 放行）→ 库存- → 自动生成应收
来料登记 → 自动生成应付
盘点 → 差异调整单 → 库存校准
```

## 7. 账目域（票 08）

### 7.1 口径

- **营收**：现金收付制——收款核销 = 营收；出库只生成应收，营收在收款时确认
- **成本**：期间制——材料按采购月汇总（来料登记单金额合计）+ 人工/制费月度手填（固定六类：人工/电费/燃气/房租/折旧/其他）
- **利润视图**：月度总览（营收-材料-人工-制费）+ 营收按客户/产品下钻；成本不下钻
- **币种**：一期单币种 RMB（订单行币种字段保留出海预留）

### 7.2 实体

| 实体 | 关键点 |
|---|---|
| 应收 | 出库确认自动生成（客户/金额）；收款单核销（部分核销=部分回款） |
| 应付 | 来料登记单自动生成（供应商/金额）；付款单核销 |
| 收款单 | 核销 + 预收双模式（覆盖 30% 定金+70% 尾款）；一步生效+冲销纠错无草稿态 |
| 付款单 | 核销 + 预付双模式（与收款单同构） |
| 对账单 | 按客户：出库明细+收款明细+期末余额；账龄分桶（30/60/90+）逾期标红无推送 |
| 导出 | 四表导出（出库/收款/来料采购/付款明细）给外部做账；不做凭证不做科目映射 |

### 7.3 事件链

```
出库确认 → 应收 → 收款单核销 → 应收结清 → 营收确认
来料登记 → 应付 → 付款单核销 → 应付结清
```

## 8. AI 能力与分期（票 02 + 票 10）

统一原则：**确定性为骨、LLM 解释**；云端 API + OpenAI 兼容网关可切换。

| 能力 | 一期路径 | 二期 | 三期 |
|---|---|---|---|
| 订单解析 | 多模态直出（qwen3-vl-flash）+ JSON Schema + 规则校验 + 低置信转人工 + 学习闭环 | — | — |
| 自然语言查数 | function calling（20-40 参数化工具） | 受控 Text-to-SQL（只读+AST+白名单+语义层） | — |
| 排产建议 | — | what-if 解释、建议生成 | 自动排产联动（LLM 规则演化） |
| 异常预警 | 规则引擎（安全库存/账龄/交期冲突标红） | LLM 解释 | ML 异常检测叠加 |
| 报表 | 利润月报摘要（模板渲染 + LLM 摘要） | — | — |

- 验收：一期订单解析直通率 ≥70%、查数准确率 ≥90%、报表无数字幻觉；二期 SQL 实用 ≥90%、解释一致 100%；三期采纳率 ≥50%
- 模型组合：DeepSeek-V4-Flash（常规）/ qwen3-vl-flash（多模态）/ qwen3-max（复杂推理）/ GLM-4.7-Flash（开发免费）
- 二期触发：数据 2-3 月积累（硬前提）+ 长尾问数信号（习惯）

## 9. 角色与端形态（票 07）

- 一级全管理员：无角色区分，所有操作所有人可做
- 免登录：局域网直接用，无密码
- 操作留痕：2-3 台 PC 各绑默认操作人（固定名单 + 下拉可覆盖）
- 报工：办公室 PC 代录（文员/计划员按纸单录）
- 端形态：一期纯 PC，不加移动端
- 远程：不开放

## 10. 数据迁移与切换（票 12）

- **只搬活数据**：主数据全量 + 在途单 + 成品期初库存快照
- 已完成旧单与旧账留 Excel 归档（余额不迁，对账单/账龄只覆盖新账）
- 系统内 Excel 导入：自动校验（必填/目录/客户/数量/交期）+ 人工抽检
- 定点切换、备齐即切（接受月中）、边用边补（主数据→期初库存→在途单）
- 旧表归档保留不再更新

## 11. 实施顺序（票 13）

### 四阶段

| 阶段 | 内容 | 验收 |
|---|---|---|
| ①地基 | Docker Compose 骨架（nginx+app+postgres）+ 一键安装脚本雏形 | docker compose up 成功 + 首页可访问 |
| ②订单线 | 技术验证票（最小全栈 CRUD）→ 主数据界面 → 订单录入/归档 → 生成草稿+审核 → 报工+状态聚合 → 列表反查（拆 4-5 张小票） | 录单→审核→报工→订单完成全流程走通（对照原型） |
| ③仓储账目线 | 出库→应收→收款、来料→应付→付款闭环 | 业务闭环 |
| ④排期AI线 | 甘特库验证 → 排程看板 → AI 一期（订单解析直通率≥70%） | 拖排 + 直通率 |

### 关键决策

- 首条线 = 订单→计划单→排期（原型已验证链路，跑通 = 技术栈全验证）
- 全部做完才执行票 12 定点切换；开发/验收用演示数据，切换日灌真实数据
- 主数据「界面」做订单线开头；主数据「真实数据」切换时灌入
- 一键脚本骨架雏形 → 后期完备

## 12. 已知代价与风险（跨票汇总）

1. 旧账留 Excel——系统对账单/账龄只覆盖切换后新账
2. 月中切换——切换当月月度统计横跨新旧两套
3. 边用边补——切换后第一周数据不完整
4. 工序耗时数值未填前，排期工期为占位提示
5. 天级粒度下换型时间折入天，多型号同日换型时排期偏粗
6. 工序产能池不区分具体设备台（二期设备级再说）
7. 免登录 + 厂内 IP 直连无 HTTPS——云翻案时必须补 HTTPS/访问控制
8. 厂内闲置电脑硬件寿命不确定——靠双备份兑底
9. 一期查数受工具集限制，长尾问题二期 Text-to-SQL 补
